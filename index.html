Why it exists

Fast agents need mechanical guardrails

AI coding agents have no institutional memory, no sense of “we already decided this,” and a bias toward output that looks right. Ungoverned, they ship code that compiles and quietly breaks what matters — tenant isolation, API stability, security posture, architectural boundaries. Governance-by-documentation fails because nobody re-reads the standards doc on edit #400.

Mechanical, not advisory

If a rule matters, a hook enforces it at the moment of action. Unenforced rules are aspirations — and the coverage matrix says so honestly.

Tiered autonomy

Most work auto-approves. Only high-blast-radius changes — schema, auth, breaking APIs, cross-boundary, frozen interfaces — block on a human.

Compiled memory

Every incident hardens the framework into a new rule or hook. Every non-obvious lesson becomes a knowledge note the next agent reads at session start.

Architecture

Three layers, each usable on its own

The constitution and process layers are pure documentation + templates — portable to any tool or none. The enforcement layer is where technology shows up; the default adapter targets Claude Code and the patterns port to git hooks or CI.

Constitution — the non-negotiablesinviolable rules · autonomy tiers · quality + security principles
Process — how work flowsSDLC gate · 6 session archetypes · task classification · DoR/DoD · waivers
Governance — decisions & reviewADR process · adversarial review · knowledge mgmt · change-control tiers
Enforcement — the teeth10 phase-aware hooks · 4 agent skills · CI backstop · stack adapters

Adoption

Phased rollout — built in

Dropping every gate on a team at once breeds --no-verify. Every hook self-grades from one config line, so you phase enforcement in over ~4 weeks as the team internalizes each tier.

Phase 1

Tracking

Hooks log, never block. Make the gates visible and tune the heuristics with zero friction.

Phase 2

Soft gates

Hooks warn loudly but still allow. Build the habit; measure how often each gate would fire.

Phase 3

Enforcing

Hooks block (exit 2). Discipline is now structural. Turn on the required CI backstop.

The teeth

10 enforcement hooks (shipped & smoke-tested)

Each blocks a specific class of violation in-session, with graded severity by phase. All ten were verified across phases 1–3 before release.

Getting started

From zero to enforcing in ~4 weeks

  1. Configure (30 min)Copy framework.config.yaml, set org/project, your boundaries, autonomy thresholds, and which stack adapters you use.
  2. Install at phase 1Run the installer. It stamps the core to .keel/, hooks to .claude/, the adapters, and the CI workflow — all in tracking mode. Commit it as one PR.
  3. Tune & advanceWeek 1 watch the gates track; tune the source/spec globs. Week 2–3 flip to soft (warn) and build habits. Week 4 flip to enforcing.
  4. Wire the CI backstopMake governance-verify a required status check so bypassed hooks still get caught at merge.
